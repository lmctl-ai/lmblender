# Host flag cutover qualification

Only --lmcode, --lmcode-schema and --lmcode-signatures select the host language
protocol. All three retired spellings fail before bytecode input is opened;
new raw schema bytes and signatures match the source compiler. Other existing
host commands, DSLB magic and .dslb filenames remain intact.

The actual original native binary was built and observed accepting retired
schema/signature modes and attempting file access under the retired execution
mode. The unchanged refusal assertions fail there and pass after the rename.
The consumer SDK was refreshed with sync-sdk.sh from canonical 20325f7; compiler
qualification checks emitted v6 capabilities, not source package-version labels.
Tutorial and API-guide copies were regenerated by their owner scripts.

Two exact lines describing the old 0.3.2 release stay historical in
RELEASE_NOTES.md. Their line hashes are the only exceptions in the shared spelling
gate; duplicate/new old-option lines still fail. No directory is excluded.

The full Linux gate passes with privately built pinned Blender/Cycles, static
Embree/OCIO/OIIO/OIDN, official signed LLVM 18 packages and CMake 3.31.10. All
required rendering/pixel/parity/budget/error checks, 303-signature parity and 287
hostile import/texture/bytecode/source cases pass. Both binaries are fully static.
For Clang, local CMake configuration supplied explicit static linker flags; no
linkage assertion was weakened. Optional CAD composition and independently
configured Blender display-reference checks remain unqualified. No visual QA
provider, release script, global install or globally installed host was used.

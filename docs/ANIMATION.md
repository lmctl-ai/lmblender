# Animation and frame output

`Mesh.keyframe_transform(frame, x, y, z, interpolation)` keys a mesh object's translation in scene units (Z up). `Material.keyframe_color(frame, r, g, b, interpolation)` keys base color channels in [0,1]. `Scene.camera_keyframe(frame, px,py,pz, tx,ty,tz, interpolation)` keys camera position and look target. Interpolation is `linear` or smoothstep `ease`. Repeated keys at the same frame replace the previous key.

`Scene.render_sequence(pattern, first, last, samples, width, height)` renders inclusive integer frames. The path pattern must contain `{frame}` or `####`; the latter is zero-padded to four digits. `Scene.render_apng(path, first, last, samples, width, height, fps)` renders the same animation into an atomically published APNG. APNG frame delay is stored as the exact rational `1/fps`. Both APIs enforce a 240-frame / 64-million total-pixel budget and use the configured deterministic render seed.

The current sequence API interpolates mesh translation, camera position/target, and material base color. `Scene.motion_blur(enabled, shutter_frames)` produces transform blur for keyed mesh translations and camera position/target; shutter duration is limited to 0.1–2 frames. On aarch64/GCC 14, GDB showed Cycles' per-ray motion interpolation occasionally receiving a time value far outside [0,1], even after disabling tree vectorization and compiling the CPU kernel at -O1. The host therefore renders nine static shutter-time samples and averages them; it does not enter the unstable per-ray interpolation path. This creates a slight multi-sample/ghosted look at fast motion rather than exact continuous per-ray blur. Mesh rotation/scale and material roughness/metallic are not keyed yet. `tests/motion_blur_quality.py` measures the animated sphere's red-mask width against the sharp control.
